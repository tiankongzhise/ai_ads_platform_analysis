# EduAdCRM 用户体验架构设计

> **项目**：EduAdCRM-MVP（教育行业广告×CRM数据平台）
> **版本**：v1.0
> **日期**：2026-04-27
> **基于**：UI设计系统 + 市场调研报告 + 技术架构 + MVP任务列表

---

## 一、现有用户体验流程断点诊断

### 1.1 诊断方法

以"用户核心目标"为主线，逐一梳理从注册到获得价值的完整路径，识别每个环节中可能让用户**迷失、卡住、挫败、流失**的断点。

> **核心用户画像**：教育培训机构负责人/市场主管，非技术背景，月广告预算1-50万，核心诉求是"看清每条广告带来多少招生"。

---

### 1.2 断点全景图

```
注册登录 → 引导配置 → 广告账户绑定 → CRM数据导入 → ROI查看 → 交叉分析 → 报表导出
   ❌ BP-1      ❌ BP-2       ❌ BP-3          ❌ BP-4        ❌ BP-5     ❌ BP-6      ❌ BP-7
```

---

### 1.3 断点详细分析

#### 🔴 BP-1：注册→引导配置 断层

**现状**：登录页只有"邮箱+密码"，注册成功后直接跳转仪表盘。

**问题**：
- 用户注册后面对空仪表盘，5个指标卡片全是"--"，**首次体验价值为零**
- 没有任何引导告诉用户"下一步该做什么"
- 引导配置（A2）在 Sprint 2 才做，Sprint 1 用户就是裸奔状态
- 登录页有"还没有账号？立即注册"但没有注册页设计

**影响**：用户注册后3分钟内流失率极高，因为看不到任何价值。

---

#### 🔴 BP-2：引导配置→广告绑定 脱节

**现状**：引导配置收集"机构名称、行业子类、主要招生产品"，但**没有引导用户绑定广告账户**。

**问题**：
- 引导完成后用户仍然面对空仪表盘
- 广告账户绑定藏在侧边栏"广告账户管理"里，新用户不知道要去那里
- 绑定广告账户需要 OAuth 授权，涉及跳转外部页面，用户可能迷失
- 没有告诉用户"绑定广告账户后才能看到ROI数据"

**影响**：用户完成引导配置后，仍然无法获得核心价值，产生"这东西没用"的印象。

---

#### 🔴 BP-3：广告账户绑定体验断裂

**现状**：广告账户管理页按平台分组（抖音/百度），点击"绑定新账户"跳转 OAuth。

**问题**：
- OAuth 授权需要跳转到巨量引擎/百度页面，授权后回调——**用户不知道自己会被跳到哪里**
- 授权失败（如 API 未审批、网络错误）没有明确的错误引导
- 授权成功后回到账户列表页，但**没有提示用户"下一步该导入CRM数据"**
- 绑定后广告数据要等凌晨定时拉取，**MVP阶段用户绑定后看到的数据仍然是空的**
- "最后同步时间"显示的是空白或"从未同步"，没有解释何时有数据

**影响**：用户绑定了广告账户，但看不到数据，以为绑定失败。

---

#### 🔴 BP-4：CRM数据导入→ROI关联 黑洞

**现状**：CRM导入是独立页面（拖拽上传→字段映射→进度条），完成后跳回线索列表。

**问题**：
- **字段映射是最大的体验断层**：用户上传的Excel列名千变万化（"手机号"vs"电话"vs"联系方式"vs"tel"），手动映射6个标准字段，操作繁琐
- 没有智能匹配建议（如自动识别"姓名"/"name"列）
- 上传完成后显示"成功31200条"但**没有告诉用户这些数据对ROI有什么用**
- 线索列表页和ROI仪表盘之间没有关联入口——用户不知道"导入的数据已经反映在仪表盘上了"
- 归因规则（"抖音"匹配巨量引擎）在设置页里，新用户完全不知道要配置

**影响**：数据导入了，但ROI计算可能因为归因规则未配置而全部归入"其他渠道"，用户看不到有意义的分析结果。

---

#### 🔴 BP-5：ROI仪表盘 空态→有态 跃迁失败

**现状**：仪表盘有5个指标卡片+2个图表+1个表格，空态显示"--"或"暂无数据"。

**问题**：
- 仪表盘同时依赖**广告数据**和**CRM数据**，缺任何一方都是空态
- 空态只有"暂无数据"文字，**没有行动引导**（如"去绑定广告账户"或"去导入CRM数据"）
- 即使两方数据都有，归因规则未配置也导致渠道对比图全是"其他"
- 日期选择默认"今日"，但广告数据是T+1拉取，**今日永远是空的**
- 没有示例数据/演示模式让用户体验"看到ROI数据是什么感觉"

**影响**：这是产品的核心页面，但80%的新用户首次看到的是空态，直接判定产品无用。

---

#### 🟡 BP-6：交叉分析 可达性差

**现状**：交叉分析在侧边栏独立入口，需要手动选择时间范围+平台+课程类型。

**问题**：
- 从仪表盘无法直接跳转到交叉分析（如点击某个广告计划排行→进入交叉分析）
- 交叉分析的筛选条件需要用户主动选择，默认可能无数据
- 没有和仪表盘共享时间范围状态
- 导出CSV是唯一操作，缺少"分享给同事"或"添加到报表"的连贯操作

**影响**：功能存在但发现率低，用户停留在仪表盘层面，无法深入分析。

---

#### 🟡 BP-7：报表→行动 缺失

**现状**：月报自动生成，可下载Excel/PDF。

**问题**：
- 报表是"终点"而非"起点"——用户下载后不知道该做什么
- 没有基于报表数据的"行动建议"（如"抖音ROI高于百度，建议将20%预算从百度转至抖音"）
- 报表和仪表盘数据不一致的风险（时间范围不同）
- 小程序端无法查看报表

**影响**：报表沦为"存档文件"，没有驱动决策和行动。

---

### 1.7 断点严重性汇总

| 断点 | 严重性 | 影响面 | 根因 |
|------|--------|--------|------|
| BP-1 注册→空仪表盘 | 🔴 致命 | 100%新用户 | 首次体验无价值 |
| BP-2 引导不连价值链 | 🔴 致命 | 100%新用户 | 功能串联缺失 |
| BP-3 绑定后无数据 | 🔴 严重 | 所有绑定广告的用户 | T+1同步+无解释 |
| BP-4 归因黑洞 | 🔴 严重 | 所有导入CRM的用户 | 隐性依赖未暴露 |
| BP-5 仪表盘空态 | 🔴 致命 | 80%+新用户 | 无数据时无引导 |
| BP-6 交叉分析可达性 | 🟡 中等 | 深度用户 | 缺少上下文跳转 |
| BP-7 报表无行动 | 🟡 中等 | 留存用户 | 缺少决策闭环 |

## 二、用户体验架构重设计

### 2.1 设计哲学：Value-First（价值优先）

> **核心原则**：用户在注册后5分钟内必须看到产品的核心价值——"ROI数据长什么样"。

这要求：
1. **先给结果，再要数据**——用演示数据让用户体验完整流程
2. **一条路径走通**——所有必要步骤串联成一条不可偏移的引导线
3. **每一步都有即时反馈**——用户永远知道"我做了什么，得到了什么，下一步该做什么"

---

## 四、关键交互模式规范

### 4.1 数据状态流转模式

所有数据展示组件必须遵循统一的状态流转：

```
加载态(骨架屏) ──▶ 空态(引导行动) ──▶ 部分数据态(渐进提示) ──▶ 完整数据态
     │                  │                    │                       │
     │                  │                    │                       │
  骨架屏动画      行动引导卡片          亮一部分+            完整图表
  +loading文字    +演示数据入口        暗一部分+提示          +下钻入口
                                     补全提示
```

**组件API规范**：
```tsx
interface DataComponentProps {
  loading?: boolean;           // 加载态
  empty?: boolean;             // 空态
  emptyAction?: {              // 空态行动引导
    label: string;
    onClick: () => void;
  };
  partial?: boolean;           // 部分数据态
  partialHint?: string;        // 补全提示文案
  demoMode?: boolean;          // 演示模式
  data?: any;                  // 完整数据
}
```

### 4.2 操作反馈模式

| 操作类型 | 反馈方式 | 时机 | 持续时间 |
|----------|----------|------|----------|
| 即时操作（点击、切换） | 按钮状态变化 | 0ms | 150ms |
| 短操作（表单提交、状态更新） | Toast 成功/失败 | 操作完成后 | 3秒自动消失 |
| 长操作（Excel导入、报表生成） | 进度条+可最小化 | 操作开始时 | 操作完成后消失 |
| 异步结果（广告数据同步） | 通知铃铛+红点 | 后台完成后 | 用户查看后消失 |
| 危险操作（删除、断开连接） | 二次确认弹窗 | 操作前 | 用户确认后 |

### 4.3 演示数据模式

**目的**：让用户在无真实数据时也能体验产品完整价值。

**实现规范**：
- 全局切换：Header右上角"演示数据/真实数据"切换开关
- 演示数据标识：所有演示数据区域加蓝色虚线边框 + "演示"角标
- 数据真实感：使用教育行业典型数据（CPE ¥30-50, ROI 1:3-6）
- 演示数据覆盖：仪表盘5个指标卡片 + 趋势图 + 渠道对比 + 排行表
- 首次触发演示：新用户注册后默认演示模式
- 退出条件：用户完成3步引导配置后，自动切换真实数据（如有）

## 九、总结

### 核心改进原则

1. **价值前置**：用户注册5分钟内必须看到ROI数据长什么样（演示数据）
2. **路径串联**：3步引导向导替代分散的独立配置，一条路走到底
3. **即时反馈**：绑定广告→立即拉7天历史数据，不等凌晨
4. **智能降低门槛**：字段自动映射+归因自动确认，减少手动配置
5. **渐进式空态**：空不是死胡同，而是"你还差这一步"的引导
6. **上下文贯通**：仪表盘→交叉分析携带筛选上下文，减少重复操作
7. **行动闭环**：报表不只是数据，还告诉你"该做什么"

### 与现有设计系统的衔接

本文档的交互设计遵循 `edu-adcrm-ui-design-system.md` 中定义的：
- 色彩系统（Primary/Secondary/语义色）
- 字体层级（数据展示用等宽数字字体）
- 间距系统（8px基准）
- 组件库（MetricCard/ChartCard/DataTable等）
- 动效系统（过渡时长与缓动函数）
- 响应式断点策略

新增的交互模式（演示数据切换、引导向导、智能映射等）需在组件库中新增对应组件，但视觉规范完全复用现有设计系统。
