# 教育广告 CRM 数据分析平台详细模块设计

## 1. 文档目的

本文档在系统架构基础上进一步说明各核心模块的职责、输入输出、内部流程、依赖关系和关键规则，帮助后续开发团队按模块实施。

## 2. 组织模块

### 2.1 职责

- 管理租户下的多级组织树。
- 支持集团、区域、学校、校区等组织类型。
- 提供组织范围查询和下级组织聚合范围。
- 为团队、线索、广告账户和 BI 提供组织维度。

### 2.2 关键规则

- 组织必须归属于一个租户。
- 组织移动时不得形成循环。
- 停用组织后，其下团队和渠道应限制新增数据，但历史数据保留。
- 组织树调整不应破坏历史 BI，历史事实表可使用组织快照维度。

### 2.3 主要接口

- 获取组织树。
- 创建组织。
- 更新组织。
- 移动组织。
- 查询组织汇总。

## 3. 团队模块

### 3.1 职责

- 管理招生团队。
- 管理团队成员与负责人。
- 管理团队可使用渠道。
- 提供线索上报归属和团队效率统计维度。

### 3.2 关键规则

- 团队必须归属于一个组织。
- 团队内手机号重复线索不得重复入库。
- 团队停用后不可继续上报线索，但历史线索仍可统计。

## 4. 广告渠道与账户模块

### 4.1 职责

- 管理组织下广告渠道。
- 保存广告账户引用。
- 展示广告账户同步状态。
- 接入已完成广告平台回调能力。

### 4.2 回调后处理

1. 接收已完成回调能力提供的平台、账户 ID、账户名称和 token 引用。
2. 校验租户和组织范围。
3. 创建或更新广告账户。
4. 写入账户同步状态。
5. 投递 `ad.sync.requested` 消息。

### 4.3 平台范围

首批平台包括：

- 抖音。
- 腾讯。
- 百度。
- 小红书。

具体 API 字段在平台接入阶段补充，不影响通用数据获取基座设计。

## 5. 广告数据获取基座模块

### 5.1 设计目标

各广告平台有不同授权规则、报表类型、时间粒度、分页方式、限流策略和字段口径。数据获取基座的目标是提供统一同步框架，同时允许平台适配器保留差异。

### 5.2 通用能力

- 同步任务创建。
- 平台 API 客户端调度。
- 请求参数生成。
- 分页与游标处理。
- 限流和退避。
- 错误分类。
- 原始报表去重。
- 原始 `jsonb` 入库。
- 同步状态更新。

### 5.3 平台适配器接口

```text
PlatformAdapter
  - platform_code()
  - supported_report_types()
  - build_request(report_type, date_range, account_context)
  - fetch_page(request, cursor)
  - extract_records(response)
  - classify_error(error)
  - rate_limit_policy()
```

### 5.4 原始数据入库规则

- 每条平台返回记录以 `raw_payload` 保存。
- 记录平台、报表类型、日期、外部实体 ID 和 payload hash。
- 不在入库阶段丢弃平台特有字段。
- 不因某个平台缺少字段而影响其他平台。

## 6. 线索导入模块

### 6.1 职责

- 接收 Excel/CSV 文件。
- 接收 API 上报线索。
- 字段映射和校验。
- 手机号标准化和哈希。
- 团队内去重。
- 写入线索和导入批次。
- 输出导入错误报告。

### 6.2 Excel 导入流程

```text
创建导入批次
  → 上传文件
  → Python 服务解析表头和前几行
  → 返回字段映射建议
  → 用户确认映射
  → 异步处理全部行
  → 写入 leads
  → 输出成功、重复、失败统计
  → 投递冲突识别消息
```

### 6.3 校验规则

- 手机号为必填字段。
- 组织和团队必须有效。
- 团队内相同手机号不得重复写入。
- 不同团队相同手机号应进入冲突流程。
- 原始字段必须进入 `raw_fields`，便于追溯。

## 7. 线索冲突模块

### 7.1 职责

- 识别跨团队相同手机号线索。
- 创建冲突组。
- 标记候选咨询和主咨询。
- 支持管理者裁定。
- 输出冲突统计指标。

### 7.2 冲突识别规则

- 按 `tenant_id + phone_hash` 查找跨团队线索。
- 若只有一个团队存在该手机号，不创建冲突组。
- 若多个团队存在该手机号，创建或更新冲突组。
- 冲突组未解决前，相关团队继续跟进时应给出提示。

### 7.3 主咨询裁定

可按以下方式裁定：

- 系统建议：首次上报。
- 系统建议：首次到校。
- 系统建议：首次报名。
- 管理者手动选择。

裁定后非主咨询自动标记为冲突量。

## 8. 归因模块

### 8.1 职责

- 将线索来源与广告渠道关联。
- 计算不同归属规则下的团队和组织归属。
- 为 BI 提供可选择的口径。

### 8.2 归因来源

- 线索来源渠道字段。
- 团队与渠道配置。
- 广告平台账户或广告计划映射。
- 管理者维护的关键词规则。
- 定制 BI 扩展包中的客户专属规则。

### 8.3 归属口径

- 首次上报。
- 首次到校。
- 首次报名。
- 手动裁定。

## 9. ETL 模块

### 9.1 职责

- 从广告原始报表、线索、冲突和归属数据抽取数据。
- 将平台字段转换为标准字段。
- 生成标准事实表和维度快照。
- 触发小时聚合和 BI 刷新。

### 9.2 ETL 批次

每次 ETL 应记录：

- 批次 ID。
- 输入数据范围。
- 源表和源记录数量。
- 转换规则版本。
- 指标版本。
- 成功和失败统计。

### 9.3 转换策略

- 广告字段按平台适配器映射到 `spend`、`impressions`、`clicks`、`conversions` 等标准字段。
- 平台无法映射的字段保留在原始层，不强行丢弃。
- 线索阶段转换为标准招生漏斗阶段。
- 组织和团队使用当前维度或历史快照，避免历史报表漂移。

## 10. BI 模块

### 10.1 标准 BI

提供以下标准看板：

- 集团总览。
- 学校对比。
- 团队效率。
- 渠道 ROI。
- 招生漏斗。
- 线索冲突。
- 归属裁定。
- 小时趋势。

### 10.2 受控配置

付费用户可配置：

- 指标显示隐藏。
- 图表类型。
- 布局。
- 看板视图。
- 筛选条件。

所有配置必须从指标目录、维度目录、数据集目录和图表注册表选择。

### 10.3 定制扩展

平台开发人员通过扩展包交付：

- 定制指标。
- 定制数据集。
- 定制图表。
- 布局模板。
- 权限规则。
- 迁移和回滚脚本。
- 测试用例。

## 11. 报表模块

### 11.1 职责

- 根据用户选择生成多种报表。
- 支持 Excel 和后续 PDF。
- 记录报表参数、数据版本、指标版本和生成结果。
- 生成行动建议。

### 11.2 报表类型

- 集团月报。
- 学校对比报表。
- 团队效率报表。
- 渠道 ROI 报表。
- 招生漏斗报表。
- 线索冲突报表。
- 归属裁定报表。

### 11.3 生成流程

```text
用户提交报表参数
  → report-service 创建任务
  → PGMQ report_generate_queue
  → 查询 BI 数据集
  → 生成文件
  → 写入对象存储
  → 更新报表状态
```

## 12. 虚拟演示账户模块

### 12.1 职责

- 创建虚拟账户。
- 接入临时广告数据。
- 限制最长 7 天有效期。
- 支持手动销毁。
- 到期自动销毁。
- 支持授权迁移到正式账户。
- 清理后只保留不含业务数据的审计结果。

### 12.2 销毁清理范围

- PostgreSQL 业务表中该虚拟租户的数据。
- OAuth token 引用和密钥。
- 对象存储中的导入文件、错误报告和导出报表。
- Redis 缓存、进度、幂等键和过期提示。
- PGMQ 中未处理或可识别的虚拟账户消息。

### 12.3 迁移规则

- 迁移必须在虚拟账户有效期内发生。
- 必须记录用户授权。
- 必须记录迁移范围和目标正式租户。
- 迁移完成后原虚拟账户仍按生命周期清理。

## 13. 审计模块

### 13.1 记录范围

- 组织、团队、渠道配置变更。
- 线索导入和 API 上报。
- 冲突裁定。
- 归属规则变更。
- BI 扩展包启用、禁用、升级、回滚。
- 虚拟账户创建、迁移、销毁。
- 敏感数据访问。

### 13.2 审计要求

审计日志应包含用户、租户、资源、动作、请求 ID、IP、时间和摘要。虚拟账户清理审计不得包含客户业务数据。
