# 接入风险、权限申请与后续建议

## 1. 主要风险

| 风险 | 影响 | 建议 |
| --- | --- | --- |
| API 权限未开通 | SDK 有接口但调用失败。 | 每个平台建立权限申请清单，开发前用测试账号逐项验证。 |
| OAuth 回调差异 | 回调字段、state、授权账户列表不同。 | 回调能力输出统一可信事件，平台差异只留在 OAuth 适配层。 |
| token 生命周期不同 | 刷新策略错误会导致同步中断。 | token 存储记录平台、过期时间、刷新语义和最后刷新结果。 |
| 报表字段口径不同 | BI 指标不可比。 | 原始层保真，ETL 层引入指标版本和平台字段映射表。 |
| 异步报表文件短期有效 | 文件过期后无法追溯。 | 生成成功后立即下载到对象存储，保存 `source_file_ref`。 |
| 限流和并发控制不足 | 平台封禁或大量失败重试。 | 按 app、账户、接口三层配置令牌桶和指数退避。 |
| 社区 SDK 可信度不足 | 安全、许可证、接口版本风险。 | 小红书社区 SDK 和百度社区 Go SDK 只作为参考，不作为默认生产依赖。 |
| SDK 快照体积大 | 仓库增长明显。 | 后续如进入工程开发，可考虑只保留官方 SDK 的需要模块或迁移到内部制品库。 |

## 2. 权限申请清单

每个平台进入编码前必须确认：

- 开发者主体、应用 ID、secret 和回调域名。
- OAuth2 授权权限、报表读取权限和多账号管理权限。
- 测试广告账户和授权广告主。
- 可调用报表接口、字段、时间窗口、分页上限和频控。
- 是否存在沙箱环境、测试白名单或行业限制。
- 是否允许保存原始返回数据和下载文件。

## 3. 适配器开发顺序

1. 实现通用 `PlatformAdapter` 接口和 `report_capabilities` 配置加载。
2. 先接巨量引擎 `account_daily` 和 `campaign_daily`，验证 OAuth、分页、原始入库和 ETL 基线。
3. 接腾讯广告 `daily_reports`，复用同一套分页和限流框架。
4. 接百度 `ReportService`，补齐 `userName + accessToken` 请求头和异步文件转存。
5. 接小红书聚光 REST 客户端，开发前先完成官方文档复核。

## 4. 数据模型补充建议

现有 `ad_platform_accounts` 和 `ad_raw_reports` 可以支撑首批接入，但建议后续设计阶段补充：

- `ad_platform_token_refs` 或密钥服务映射表，记录 token 元数据和过期时间。
- `ad_report_capabilities`，保存平台报表能力、最大时间跨度、粒度、字段和限制。
- `ad_external_async_tasks`，保存外部异步报表任务 ID、状态、下载文件引用和过期时间。
- `ad_sync_rate_limits`，保存平台、接口、账户维度的频控策略。

## 5. 验收标准

首批平台接入达到以下状态即可进入开发：

- 每个平台至少有一个测试账号完成授权。
- 每个平台至少拉取一种日报原始数据并写入 `ad_raw_reports`。
- 重复拉取同一日期不会重复产生业务记录。
- token 过期前可自动刷新，刷新失败能进入重授权状态。
- 报表同步失败可查看平台错误码、请求 ID、重试次数和失败原因。
- BI 层只消费 ETL 标准事实表，不直接依赖平台原始字段。
