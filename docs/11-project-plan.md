# 教育广告 CRM 数据分析平台项目计划

## 1. 文档目的

本文档按照瀑布模型组织项目阶段、里程碑、交付物、依赖关系、风险和演进路径，为后续项目管理和研发排期提供基础。

## 2. 瀑布模型阶段

项目采用经典瀑布模型作为文档和阶段框架，但开发实施可在每个阶段内部采用迭代方式推进。

```text
可行性分析
  → 需求规格
  → 概要设计
  → 详细设计
  → 开发实现
  → 集成测试
  → 部署上线
  → 运维迭代
```

## 3. 阶段一：可行性分析

### 3.1 目标

确认项目商业、技术、经济和运营可行性。

### 3.2 交付物

- 项目概述。
- 可行性分析。
- 初步风险清单。
- 技术路线确认。

### 3.3 完成标准

- 明确 README 为主需求来源。
- 明确 PostgreSQL、Redis、PGMQ、Go、Python、React 技术基线。
- 明确鉴权和广告回调不重复建设。

## 4. 阶段二：需求规格

### 4.1 目标

完成业务功能、非功能需求、数据需求和约束条件定义。

### 4.2 交付物

- 需求规格说明书。
- 用户角色和权限范围。
- 核心业务流程。
- BI 需求清单。
- 虚拟演示账户生命周期需求。

### 4.3 完成标准

- 覆盖组织、团队、渠道、线索、冲突、归属、广告数据、ETL、BI、报表、虚拟账户。
- 普通用户不可写 SQL 的限制明确。
- 多广告平台原始数据 `jsonb` 存储策略明确。

## 5. 阶段三：概要设计

### 5.1 目标

完成系统总体架构和服务边界设计。

### 5.2 交付物

- 系统架构设计。
- 服务划分。
- Go/Python 职责划分。
- 数据流和消息流。
- 部署拓扑。

### 5.3 完成标准

- 服务可独立部署和测试。
- PGMQ 队列划分清晰。
- Redis 使用场景明确。
- 广告数据获取基座设计明确。

## 6. 阶段四：详细设计

### 6.1 目标

完成数据库、API、消息和模块详细设计。

### 6.2 交付物

- 数据库设计。
- API 与消息设计。
- 详细模块设计。
- 前端设计。
- 测试计划。
- 部署运维设计。

### 6.3 完成标准

- 核心表结构和索引明确。
- API 分组和通用错误模型明确。
- 消息 schema、重试和幂等明确。
- 前端页面和 BI 配置方式明确。

## 7. 阶段五：开发实现建议

### 7.1 MVP 目标

先打通教育行业广告招生数据闭环：

- 组织树。
- 招生团队。
- 广告渠道和账户引用。
- 一个到两个广告平台数据基座。
- Excel 线索导入。
- 团队内去重和跨团队冲突。
- 基础归属规则。
- ETL 标准化。
- 标准 BI 看板。
- 基础报表。
- 虚拟账户创建和销毁。

### 7.2 实现优先级

#### P0 核心闭环

- 组织、团队、渠道。
- 广告账户回调接入。
- 广告同步基座。
- Excel/API 线索上报。
- 线索去重和冲突识别。
- ETL 标准层。
- 集团总览、渠道 ROI、团队效率。

#### P1 管理增强

- 归属裁定多口径。
- 小时聚合。
- 招生漏斗。
- 线索冲突看板。
- 报表中心。
- 虚拟账户迁移。

#### P2 商业化能力

- 付费 BI 配置。
- 租户定制 BI 扩展包。
- 行动建议。
- 更多广告平台适配。
- 更细粒度权限和审计。

## 8. 阶段六：集成测试

### 8.1 目标

验证跨服务、跨数据层和端到端业务流程。

### 8.2 交付物

- 测试报告。
- 性能测试报告。
- 安全测试报告。
- 虚拟账户清理验证报告。
- 上线缺陷清单。

### 8.3 完成标准

- 核心 E2E 通过。
- 多租户隔离通过。
- BI 与报表口径一致。
- 虚拟账户清理无业务数据残留。

## 9. 阶段七：部署上线

### 9.1 目标

完成生产部署和首批租户上线。

### 9.2 交付物

- 部署脚本。
- 环境配置。
- 数据库迁移记录。
- 监控告警配置。
- 回滚预案。
- 运维手册。

### 9.3 完成标准

- 服务健康检查正常。
- 数据库备份有效。
- 队列消费正常。
- Redis 缓存正常。
- 告警链路可用。

## 10. 阶段八：运维迭代

### 10.1 目标

基于试点租户反馈持续优化产品。

### 10.2 重点

- 优化广告平台适配稳定性。
- 优化 Excel 导入体验。
- 丰富 BI 指标和报表。
- 完善冲突裁定流程。
- 完善虚拟账户迁移和清理。
- 引入更多平台和定制 BI。

## 11. 关键依赖

| 依赖 | 影响 | 处理方式 |
| --- | --- | --- |
| 已完成鉴权能力 | 所有 API 权限依赖 | 提前冻结鉴权上下文契约。 |
| 已完成广告回调能力 | 广告账户接入依赖 | 定义回调结果内部契约。 |
| 广告平台 API 权限 | 广告数据同步依赖 | 使用 Mock 和沙箱并行开发。 |
| PostgreSQL JSONB 和 PGMQ | 数据与队列基础 | 开发环境优先搭建。 |
| BI 指标口径 | 看板和报表依赖 | 指标目录版本化。 |

## 12. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 平台 API 差异过大 | 数据获取基座统一框架，平台适配器独立实现。 |
| 原始数据字段频繁变化 | `jsonb` 保真存储，ETL 映射版本化。 |
| 线索冲突规则复杂 | 先实现手机号冲突和基础归属，再扩展规则。 |
| BI 需求快速变化 | 指标、维度、数据集和图表注册表元数据化。 |
| 微服务协调成本高 | P0 阶段保持服务边界清晰，接口契约先行。 |
| 虚拟账户数据清理不完整 | 清理任务、清理验证和审计作为上线门禁。 |

## 13. 里程碑建议

### M1 文档与架构冻结

- 完成核心文档。
- 冻结技术基线。
- 冻结核心数据模型。

### M2 核心基础设施

- PostgreSQL、Redis、PGMQ、对象存储就绪。
- 服务模板和 CI 就绪。
- 鉴权和回调接入契约验证。

### M3 数据闭环 MVP

- 广告数据同步。
- 线索导入。
- 冲突识别。
- ETL 标准化。
- 基础 BI。

### M4 管理与报表

- 归属裁定。
- 小时聚合。
- 报表中心。
- 虚拟账户完整生命周期。

### M5 商业化扩展

- 付费 BI 配置。
- 租户定制 BI。
- 更多平台适配。
- 高级审计和监控。

## 14. 后续演进路径

### 14.1 数据平台增强

- 引入更强的分析存储。
- 按租户或时间分区优化。
- 指标计算服务独立扩容。

### 14.2 平台生态增强

- 接入更多广告平台。
- 接入企业微信、飞书、钉钉或第三方 CRM。
- 提供开放 API。

### 14.3 智能分析增强

- 行动建议从规则型升级为模型辅助。
- 增加预算优化建议。
- 增加异常检测和预测分析。
