# 教育广告 CRM 数据分析平台测试计划

## 1. 文档目的

本文档定义平台测试目标、测试范围、测试类型、关键用例、验收标准和质量门禁。测试计划覆盖后端微服务、前端、数据库、PGMQ、Redis、ETL、BI、报表、权限隔离和虚拟账户生命周期。

## 2. 测试目标

- 验证 README 中的核心需求均被实现。
- 验证微服务边界清晰且服务可独立测试。
- 验证 PostgreSQL、Redis、PGMQ 的使用符合架构设计。
- 验证广告原始数据 `jsonb` 保真入库，ETL 后标准数据正确。
- 验证线索冲突和归属裁定准确、可审计。
- 验证 BI 指标、报表和缓存结果一致。
- 验证多租户隔离和虚拟账户清理安全可靠。

## 3. 测试范围

### 3.1 范围内

- Go 服务 API。
- Python 服务 API 和 worker。
- PostgreSQL schema、迁移和约束。
- Redis 缓存、短期状态和幂等控制。
- PGMQ 消息生产、消费、重试和失败处理。
- 前端页面、交互和图表。
- ETL 和 BI 指标。
- 报表生成。
- 虚拟账户创建、迁移和销毁。

### 3.2 范围外

- 已完成鉴权系统内部实现。
- 已完成广告平台回调系统内部实现。
- 广告平台外部 API 的真实稳定性保证。

对已完成能力只做接入契约测试。

## 5. 核心测试场景

### 5.1 组织树

| 场景 | 预期 |
| --- | --- |
| 创建集团、学校、校区多级组织 | 组织树正确返回。 |
| 将组织移动到自身子节点下 | 请求失败。 |
| 停用组织后新增团队 | 按规则拒绝或提示。 |
| 集团管理者查看下级汇总 | 包含所有授权子组织。 |

### 5.2 线索上报

| 场景 | 预期 |
| --- | --- |
| 团队首次上传手机号 | 创建线索并生成唯一线索 ID。 |
| 同团队重复上传手机号 | 不重复创建，记录重复。 |
| 不同团队上传相同手机号 | 创建或更新冲突组。 |
| Excel 字段缺少手机号 | 行失败并进入错误报告。 |
| API 重复提交同一幂等键 | 返回同一处理结果。 |

### 5.3 冲突裁定

| 场景 | 预期 |
| --- | --- |
| 按首次上报裁定 | 最早上报线索为主咨询。 |
| 手动选择主咨询 | 主咨询更新，其他标记冲突量。 |
| 裁定后查看审计 | 有裁定人、时间、依据。 |
| 非授权用户裁定 | 请求拒绝。 |

### 5.4 广告数据同步

| 场景 | 预期 |
| --- | --- |
| 回调成功后创建账户 | 账户引用创建或更新。 |
| 回调成功后投递同步消息 | PGMQ 中出现同步任务。 |
| 平台 API 返回限流 | 任务进入重试。 |
| 平台字段新增 | 原始 `jsonb` 保存新增字段。 |
| 重复拉取同一报表 | 不产生重复原始记录。 |

### 5.5 ETL 与 BI

| 场景 | 预期 |
| --- | --- |
| 原始广告数据进入 ETL | 标准事实表生成正确。 |
| 线索阶段变化 | 漏斗指标刷新。 |
| 归属规则切换 | BI 按所选口径变化。 |
| Redis 缓存过期 | 自动回源或刷新。 |
| 指标公式版本升级 | 历史报表可追溯旧版本。 |

### 5.6 报表

| 场景 | 预期 |
| --- | --- |
| 创建月报任务 | 任务进入 PGMQ。 |
| 报表生成成功 | 文件写入对象存储。 |
| 生成失败 | 状态失败并记录错误。 |
| 下载无权限报表 | 请求拒绝。 |
| 报表指标与 BI 页面比较 | 同口径结果一致。 |

### 5.7 虚拟账户

| 场景 | 预期 |
| --- | --- |
| 创建虚拟账户 | 有效期不超过 7 天。 |
| 到期自动清理 | 业务数据、token、文件、缓存、队列残留清理。 |
| 手动销毁 | 进入销毁流程并记录审计。 |
| 授权迁移到正式账户 | 数据迁移到目标正式租户。 |
| 迁移后原账户 | 仍按虚拟账户规则清理。 |
| 清理审计 | 不包含业务数据。 |

## 6. 性能基准

第一阶段建议基准：

- BI 首屏热点看板：缓存命中时 P95 小于 1 秒。
- 线索导入：5 万行文件异步处理可在可接受时间内完成，并提供进度。
- 小时聚合：每小时任务在下一小时开始前完成。
- PGMQ 消费：单队列 worker 可横向扩展，重复消息处理幂等。
- 报表生成：常规月报在后台异步完成，前端不阻塞。

具体数值可在试点客户数据规模明确后细化。

## 7. 测试数据

应准备：

- 多级组织树数据。
- 多团队重复手机号线索。
- 不同阶段线索。
- 多平台广告原始报表样例。
- 平台字段缺失和字段新增样例。
- BI 指标标准答案数据集。
- 虚拟账户清理专用数据。

测试数据不得使用真实客户手机号明文。

## 8. 自动化与质量门禁

合并前质量门禁：

- 单元测试通过。
- 数据库迁移测试通过。
- API 契约测试通过。
- 消息 schema 校验通过。
- 多租户隔离核心用例通过。
- 前端关键页面构建通过。

上线前质量门禁：

- E2E 核心流程通过。
- 性能基准通过。
- 虚拟账户清理验证通过。
- 备份恢复演练通过。
- 回滚脚本验证通过。

## 9. 缺陷分级

| 等级 | 定义 |
| --- | --- |
| P0 | 数据泄露、账务级错误、核心流程不可用、虚拟账户清理失败。 |
| P1 | 广告同步、线索导入、冲突裁定、BI 核心指标异常。 |
| P2 | 非核心页面错误、部分报表异常、体验问题。 |
| P3 | 文案、样式、低影响兼容性问题。 |

## 10. 验收标准

- README 中每项需求均有实现和测试覆盖。
- PostgreSQL、Redis、PGMQ、JSONB、ETL、Go/Python 分工符合设计。
- 核心业务闭环能端到端跑通。
- 多租户隔离和虚拟账户清理通过安全验证。
- BI 指标和报表口径可解释、可追溯。
